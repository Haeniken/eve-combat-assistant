# Дальность, нейтрализаторы и скорость

Показатели относятся к выбранному примеру фита противника. Его навыки считаются V. Это оценка опубликованной сборки: установленное сейчас вооружение и заряды могут отличаться. Для Abyssal используются обычные аналоги, указанные в предупреждении.

## Дальность оружия

На линейке показана дальность самого дальнобойного установленного боевого оружия. Для сборки с боевыми дронами без пушек и ракет вместо неё показана дальность управления дронами с меткой «ДРОНЫ». Нейтрализаторы, электронная борьба и вспомогательные скрипты в дальность оружия не входят. Состав урона выше относится к заряду выбранного примера, включая его дронов; дальний заряд может наносить другие типы урона.

Для каждого установленного оружия перебираются все опубликованные совместимые боевые заряды из каталога, с проверкой группы и размера. Наличие заряда в трюме примера не требуется. Каждый вариант пересчитывается dogma-движком с полным фитом: учитываются навыки V, бонусы корпуса, модули, риги, загруженные вспомогательные скрипты и штатные штрафы. Нельзя подставлять T2-заряд в орудие, которое его не принимает. Среди вариантов выбирается наибольшая дальность.

| Оружие | Показанный рубеж |
| --- | --- |
| Пушки с falloff | Optimal + 2 × falloff; помечается ≈ |
| Оружие без falloff, например disintegrator или Vorton | Модифицированный optimal |
| Ракеты | Верхняя оценка пути до неподвижной цели с разгоном и округлением времени полёта; помечается ≈ |
| Смартбомбы | Радиус действия установленного модуля |

У пушек с falloff нет конечной границы попаданий. На optimal + 2 × falloff шанс попадания при идеальном tracking составляет 6,25%, ожидаемый урон — около 6% номинального. Выбранная граница — удобное приближение для оценки кайта, а не гарантированно безопасная дистанция. Tracking, сигнатура и движение цели в этом числе не моделируются.

Для ракет берутся модифицированные скорость `v`, время полёта `t`, масса `m` и agility `a`. Радиус корабля `r` учитывает появление ракеты из центра корпуса. Верхнее время `T = ceil(t + r/v)`, продолжительность разгона `A = min(T, m*a/1e6)`, путь `R = max(0, v*(T - A/2) - r)`. Для автонаводящихся ракет дополнительно применяется их предел дальности. На верхнем рубеже часть ракет может не долететь из-за серверного округления. Погоня, скорость сближения, дальность захвата цели и помощь других кораблей здесь не моделируются. Рубеж описывает оружие, а не полный сценарий боя.

Перегрев дальности вооружения специально не включается; состояние остальных модулей сохраняется из выбранного фита. В подсказке перечислены оружие, выбранный дальний заряд и его дальность. Ошибки отдельных вариантов сохраняются в подробном дебаге и отмечаются в подсказке.

Механику сверяли с первичными реализациями Pyfa: [дальность ракет](https://github.com/pyfa-org/Pyfa/blob/master/eos/saveddata/module.py) и [применение урона](https://github.com/pyfa-org/Pyfa/blob/master/graphs/data/fitDamageStats/calc/application.py). Код Pyfa в приложение не переносился.

## Скорость

Таблица «ЕГО / ТВОЯ» сравнивает два фита в одинаковых внешних условиях:

- **База**: все AB/MWD выключены; пассивные бонусы и штрафы остальных модулей и ригов сохранены.
- **AB / MWD**: по одному двигателю без перегрева. При двойном разгоне оба двигателя одновременно не включаются.
- Противник: все навыки V, без неизвестных имплантов и бустеров.
- Свой корабль: загруженная карта навыков персонажа, выбранные импланты и бустеры из существующего профиля.

Клока, цино, порталы, bastion/siege/triage, промышленные ядра, doomsday и Clone Vat Bay считаются выключенными для оценки свободного движения. В публичной потере их фактическое состояние неизвестно; автоматически включённая цина не должна обнулять оценку скорости. Список отключённых для этого сценария модулей есть в дебаге. Исходный фит сохраняется.

Для многорежимных эсминцев при сравнении скорости по умолчанию выбирается Propulsion Mode на обеих сторонах. Режим — отдельный dogma-объект из SDE; его модификаторы проходят через тот же расчётчик, включая реальные навыки своего персонажа. Множитель вручную не подставляется. Это допущение описано здесь и в дебаге; в подсказку оно не добавляется.

Если карта собственных навыков не загружена, в колонке «ТВОЯ» стоит прочерк; профиль V не выдаётся за реальные навыки. Внешние сетки, скрамблеры, бонусы флота и перегрев не моделируются.

Более высокая скорость противника выделяется янтарным числом и рамкой карточки; преимущество своего корабля — бирюзовым числом. Сравнение идёт отдельно для каждой строки, после округления до показанных м/с. При равенстве выделения нет. Надпись «ОН БЫСТРЕЕ» и дополнительные символы не выводятся.

Если режимы двигателей различаются, подпись строки содержит его режим / твой режим, например `AB/MWD`. При отсутствии такого типа двигателя на одной стороне для неё берётся доступный двигатель с наибольшей скоростью; без двигателя — база. Разные пары показываются отдельными строками. Подсказка объясняет порядок колонок.

Это сравнение возможностей фитов по прямой, а не измерение текущей скорости в игре. Рекомендация боевой дистанции использует приближённую модель боя; показанная скорость не обещает удержание дистанции.

## Дроновые сборки

Если в примере есть боевые дроны или усилитель их урона, но нет установленного боевого оружия в верхних слотах, поле «ЕГО УРОН» показывает «ДРОНЫ». При недоступном сравнении вместо общего сообщения об ошибке отображается «ДРОНОВАЯ СБОРКА»; резисты и скорость остаются доступны.

Вылетевшие дроны могут отсутствовать в killmail. Модули усиления их урона позволяют определить дроновую сборку, но не восстановить состав дронов или точный DPS.

Дальность управления берётся из dogma-показателя `summary.drones.range`: полный фит, бонусы корпуса, навыки V, модули и риги. Для обычного корабля без модулей дальности это 60 км, с Drone Link Augmentor II — 84 км. Это дальность выдачи команды, а не граница исчезновения урона: уже атакующие дроны могут преследовать цель дальше. Для команды атаки также нужен захват цели. Дальность управления не описывает оптимал самих дронов и применение их урона.

## Нейтрализаторы

Формат: `2× Light · до 5,0 км`. Размеры — Light, Medium, Heavy и Capital. Нейтрализаторы разных размеров или дальностей показаны отдельными строками: дальность одного длинного модуля не присваивается всем остальным. Считаются установленные активные модули выбранного примера, без дронов.

Дальность сохраняет принятую в боевой модели оценку `optimal + 0,25 × falloff`. Это не жёсткий предел: в зоне falloff эффект постепенно снижается. В подсказке доступны optimal и falloff каждой группы.

Подробная диагностика `comparison_ready` содержит `weapon_range` (источники, методы, заряды, число попыток и ошибки), `neutralizers`, `fitted_speed` противника и `own_fitted_speed`. Расчёты остаются локальными и используют существующие кеши, новых HTTP-запросов для этих показателей нет.

## Компактный HUD

Линейка показывает текущую дистанцию фиолетовой бусинкой, рекомендацию бирюзовым диапазоном и дальность оружия противника янтарной меткой. Тонкие линии выше отмечают скрам, сетку и нейтрики выбранного фита противника. Подписи стоят перед линиями; нейтрики жёлтые. Отдельная бирюзовая линия показывает максимальную дальность своего поинта или скрама. Отсутствующие модули не занимают строк. Масштаб включает показанные дальности. Состояние установленных модулей, навыки и бонусы берутся из результатов расчётчика; для своего корабля используется собственный профиль навыков. Нейтрики сохраняют условный рубеж optimal + ¼ falloff.

Принятое расстояние и числовая подпись обновляются на каждом успешном чтении OCR. Только положение бусинки интерполируется с плавным торможением за время до 140 мс; новый результат меняет конечную точку текущего движения без очереди. На коротких интервалах OCR длительность перехода сокращается до 80% интервала. При смене цели положение задаётся сразу. Мягкое свечение пульсирует с периодом 3,6 секунды, размер бусинки постоянный. Перерисовка запрашивается только у видимого индикатора: до 60 кадров/с во время движения и 20 кадров/с для свечения. Дополнительных кадров OCR или сетевых запросов нет.

Звуки используют принятые расстояния, а не промежуточные положения анимации. Первый замер задаёт исходное состояние. Для повторного пересечения нужен выход за полосу гистерезиса: 2% дальности, минимум 100 м, максимум 500 м. Между звуками проходит не меньше 1,4 секунды. Одновременные события выбираются по приоритету: скрам/сетка, потеря своего поинта, нейтрик. При пропуске распознавания, смене цели, фита или настроек состояние пересечений сбрасывается; сохранённая исчезнувшая цель не подаёт звук. Сигналы — короткие WAV, воспроизводятся Windows асинхронно из памяти; отдельная аудиобиблиотека не требуется.

Его и свой урон используют палитру резистов: EM — голубой, THERM — коралловый, KIN — серо-голубой, EXP — янтарный. Свой профиль берётся из того же кандидата фита, который выбрал рекомендацию боеприпаса, с учётом оружия и выбранных дронов. Это доли DPS до резистов и применения урона, а не сумма одних зарядов. Для дроновой сборки поле противника показывает «ДРОНЫ»; при прочих отсутствующих данных отображается прочерк. Поле `outgoing_percentages` доступно в подробном дебаге совета.


## Процент побед корпусов

Рядом с названием противника показана доля побед текущего собственного корпуса против корпуса цели. Сборки, соло-рейтинг и выбор популярного фита в этот показатель не входят. Источник — опубликованные дневные архивы zKillboard; окно — последние 365 полных дней UTC. Начальная годовая выборка подготовлена вместе с поставкой.

В запись входят известные корпуса с обеих сторон, персонаж-жертва и ровно один уникальный атакующий игрок. Капсулы, шаттлы и корветы исключаются с обеих сторон. Повторы killmail ID не увеличивают число исходов. При наличии меток отбрасываются npc, awox, padding и ganked; также отбрасывается запись с последним ударом CONCORD. NPC среди остальных атакующих допустимы. Не отражённую в killmail поддержку определить нельзя.

Если X уничтожил Y, это победа X и поражение Y. Для собственного X отображается `100 × W(X,Y) / (W(X,Y) + W(Y,X))`, округлённое до целого процента. Для обратной пары стороны меняются местами. Нужны минимум 50 исходов на пару; при меньшей выборке отображается прочерк с числом доступных записей в подсказке. Для двух одинаковых корпусов показатель равен 50%, а число боёв считается без удвоения.

Процент описывает опубликованные исходы с уничтожением корабля. Бои без потерь, тактика, помощь, выбор противников и текущие сборки неизвестны. В сыром архиве могут отсутствовать метки zKillboard. Данные разных патчей объединены в пределах года.

### Калибровка цветов

Палитра общая с SOLO: красный, оранжевый, жёлтый, зелёный, бирюзовый, синий, фиолетовый. 50% всегда относится к зелёному уровню. Для контрольного распределения берутся разные корпуса с минимум 50 исходами и хотя бы 5 победами с каждой стороны. Этот последний порог относится только к калибровке: наблюдаемые 0% или 100% при достаточном числе боёв доступны в интерфейсе.

Каждая пара имеет одинаковый вес. По абсолютному отклонению доли побед от 50% вычисляются квартили 25%, 50% и 75%. Они задают симметричные неокруглённые границы вокруг 50%; пороги округляются до целого процента. Цвет определяется по показанному целому числу. Если пороги совпали или контрольных пар меньше 30, сохраняется предыдущая пригодная калибровка. Стартовые границы и сведения о выборке находятся в `resources/rating-tiers.json`.

### Хранение и обновление

В комплект входят дневные суммы по парам корпусов; годовые raw-архивы и ID пилотов для этого показателя не поставляются. Основная база сборок по-прежнему хранит свой выбранный период. Обновление клиента скачивает новые и изменённые дни выбранного периода; отдельная загрузка года ради калибровки не выполняется.

Суммы изменённого дня заменяются целиком. Локальная версия дня закрывает все его старые суммы из комплектной базы, включая исчезнувшие пары. Не прошедший проверку архив не заменяет пригодные суммы. После обновления программа локально пересчитывает распределение цветов по доступному годовому окну; при выходе старых дат за окно они не участвуют в расчёте. Выбор цели читает только готовые суммы из SQLite. В подробной диагностике есть `hull_matchup_ready`, `hull_matchup_recalibrated` и `range_crossing_sound`.

### Комплектная контрольная выборка

Период 30.10.2025–29.10.2026: 6 089 675 доступных killmail, 1 016 104 подходящих исхода и 34 980 пар корпусов, включая зеркальные. Цветовая калибровка использует 1 641 пару с 369 873 исходами, прошедшую оба порога. Все 365 дней сверены с опубликованными дневными итогами; при расхождении проверены ID индексированных killmail. Дополнительные записи raw-архива сохраняются, недостающие индексированные записи получены через публичный ESI по их hash.

| Винрейт | Цвет |
| --- | --- |
| 0–8% | Красный |
| 9–19% | Оранжевый |
| 20–35% | Жёлтый |
| 36–63% | Зелёный |
| 64–79% | Бирюзовый |

Это стартовые пороги поставки. После обновления базы клиент пересчитывает их по локальной годовой выборке; 50% остаются зелёными. Эти границы относятся к корпусам. Границы SOLO рассчитаны отдельно по lifetime-оценкам контрольных пилотов и приведены в [документации рейтинга](pilot-rating.md).
