# Соло-рейтинг пилота

В кружке показана собственная оценка EVE Combat Assistant по соло-статистике zKillboard за всё время. Это четырёхзначный показатель результатов и опыта, а не официальный ELO zKillboard: оценки соперников и история смены рейтинга в расчёте не участвуют.

## Данные и расчёт

Источником служит `GET https://zkillboard.com/api/stats/characterID/{id}/`. Ник разрешается через ESI; ID ответа проверяется, чтобы не присвоить статистику другого пилота. Используются `soloKills` и `soloLosses` (при их отсутствии — `shipsDestroyedSolo` и `shipsLostSolo`). Общие убийства, очки, стоимость уничтоженного и Dangerous/Snuggly не увеличивают соло-рейтинг.

Обозначения: `W` — соло-убийства, `L` — соло-потери, `N = W + L`.

- Сглаженная доля успеха: `Q = (W + 5) / (N + 10)`. Десять условных наблюдений с равным исходом уменьшают влияние небольшой выборки.
- Множитель опыта: `E = (N + 10) / (N + 150)`. Он приближается к единице с ростом числа соло-боёв.
- Сначала вычисляется сила результатов и опыта: `S = Q × E = (W + 5) / (N + 150)`. Затем `P(S)` — относительная позиция среди реальных контрольных пилотов, от 0 до 1. Между соседними значениями используется линейная интерполяция; одинаковым значениям соответствует средний ранг. Нижний и верхний края контрольной выборки задают 0 и 1; результаты за её пределами ограничиваются этими краями.
- Рейтинг: `R = 1000 + floor(7999 × P(S))`, от 1000 до 8999. Диапазон 9000–9998 зарезервирован для будущего расширения модели. Текущая модель не выдаёт 9999.

Число показывается при `N ≥ 20` и `W ≥ 5`; иначе отображается нейтральное «—». Отсутствие соло-истории не означает низкий навык. При одинаковом соотношении побед и потерь большая выборка повышает оценку. Дополнительная победа не уменьшает оценку, дополнительная потеря её не повышает. Лучший результат в текущей контрольной выборке получает 8999; более сильные результаты пока тоже ограничены 8999. Это максимум этой версии, а не доказательство мировой позиции пилота. 9999 недостижимо. Рейтинг не является процентом или вероятностью победы.

| Рейтинг | Цвет |
| --- | --- |
| 1000–2499 | Красный |
| 2500–3999 | Рыжий |
| 4000–5499 | Жёлтый |
| 5500–6999 | Зелёный |
| 7000–7999 | Бирюзовый |
| 8000–8999 | Фиолетовый |

## Калибровка на реальных пилотах

Контрольная выборка от 28.10.2026: запрошены lifetime-агрегаты **180 реальных персонажей**, **39** из них удовлетворяют минимальной соло-выборке. Кандидаты выбраны воспроизводимо: уникальные ID пилотов-жертв из готовой базы всех корпусов сортируются по фиксированному хешу ID, берутся первые 180. Число их локальных потерь не меняет вес. Данные самих профилей — за всю историю, а не за период базы фитов.

Это контрольная выборка активных пилотов, а не полный мировой рейтинг и не подборка только знаменитых PvP-пилотов. Она даёт эмпирические границы и распределение шкалы; размеры выборки и смещение из-за отбора среди жертв ограничивают точность сравнения. В ресурсе `resources/pilot-rating-reference.json` сохранены анонимные соло-счётчики, сила и узлы интерполяции. Исходные ответы и аудит получения остаются в локальном build-каталоге. Калибровка заморожена для версии: во время боя приложение не собирает общую статистику и не перекачивает контрольную выборку. Это не добавляет сетевой нагрузки к выделению пилота. Кешированная оценка пересчитывается по встроенной версии шкалы.

## Плашка формата боя

При наличии минимум 20 общих убийств:

- «БЛОБ 10+»: больше половины убийств помечены `labels["#:10+"].shipsDestroyed`, то есть совершены с 10 и более атакующими.
- «ГРУППА»: не менее 90% убийств несоло, если условие блоба не выполнено.

Показатель `#:10+` накопительный: `#:25+`, `#:50+` и следующие интервалы к нему повторно не прибавляются. Если поле отсутствует, размер блоба не выдумывается: может быть показан только признак группы. `avgGangSize` показывается как оценка zKillboard в подсказке и не влияет на рейтинг. Цвет кружка зависит только от соло-оценки. Рядом с расстоянием показана компактная плашка: сине-серая «ГРУППА» или янтарная «БЛОБ 10+». Она не добавляет отдельную строку, не меняет цвет SOLO и может присутствовать при «—» вместо числа. У плашки нет всплывающей подсказки. «ГРУППА» не означает строго 2–9 атакующих: при недостатке данных о размере это лишь преобладание несоло-убийств. Отсутствие плашки не доказывает, что пилот летает соло. Обе метки описывают историю убийств, а не текущий состав флота.

## Ограничения и загрузка

Метка solo zKillboard означает одного атакующего игрока с условиями zKillboard; NPC и не отражённая в killmail поддержка возможны. При соло-потере состав союзного флота жертвы не виден. Поэтому эти счётчики дают приближение к соло-эффективности, а не подтверждённую статистику честных дуэлей. Масштаб, опыт противников, альты и фарм не восстанавливаются из агрегатов. Шкала помогает быстро ориентироваться; она не заменяет контекст боя.

Сначала показываются локальные популярные фиты и сохранённая оценка того же пилота. Статистика пилота запрашивается в фоне, независимо от результата поиска его фита. Ответы API кешируются на час; повторное выделение использует этот кеш. При ошибке обновления сохраняется доступная оценка, причина видна при наведении. Возраст данных и формула в интерфейсе не показываются. Переключатель находится в «Данные → Показывать соло-рейтинг пилота из zKillboard». В подробной диагностике есть трассировка запроса, результат, соло-счётчики и признаки группы.

Первичные источники: [API zKillboard](https://zkillboard.com/api/docs/), [расчёт статистики zKillboard](https://github.com/zKillboard/zKillboard/blob/main/cron/6.queueStats.nolock.php), [отображение Dangerous/групп](https://github.com/zKillboard/zKillboard/blob/main/templates/components/stats_box.pug), [условия метки solo](https://zkillboard.com/information/faq/#solo).
